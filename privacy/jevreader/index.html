JevReader Privacy Policy

Effective date: September 2026 · Version 1.0 · Applies to the JevReader web app and its Jev analysis API

In short: The complete PDF stays in your browser. JevReader sends only bounded selected source text, sentence IDs, a document hash, a section identifier and your reading objective to its analysis endpoint so Jev can return structured reading signals.

Overview

JevReader is a browser-based PDF reader from Ziduri. It renders and parses the PDF you explicitly open, identifies original passages that may be valuable for your chosen reading objective, and can download a locally highlighted copy. No account is required for the current pilot.

What data is processed locally

  • PDF content: the file you choose is held in browser memory so it can be rendered, parsed and exported.
  • Document metadata: a SHA-256 document identifier, the selected filename, page count and parsed structure are used to associate the document with its local cache.
  • Reading analysis: sentence coordinates, semantic roles, scores, the selected reading objective and completed analysis results are stored locally when caching is available.
  • Export data: the original PDF bytes and visible highlight rectangles are processed locally only when you choose to export.

JevReader does not ask for your name, email address, account credentials or payment information.

What leaves the browser

When you start intelligent reading, the browser sends bounded analysis requests to JevReader's /api/jev/analyze endpoint. Each request contains selected sentence IDs and their source text, the document hash, a section ID and the reading objective. The endpoint forwards the approved structured questions and selected source text to TypeSafe's Jev API, then returns sanitized judgements.

The complete PDF, its filename and the browser's local cache are not uploaded to Ziduri's server. Exact-text find runs over the locally parsed sentences and is not sent as a search query for the current pilot.

Where data is stored

PDF bytes, parsed document structures and completed analysis are held in your browser's memory and IndexedDB. JevReader does not maintain a document database, object store or cloud document library. Closing the document clears its in-memory bytes; clearing the site's browser data removes the locally cached metadata and analysis.

The deployed app and analysis proxy run on Cloudflare Workers and Static Assets. The proxy is designed to be stateless and does not persist document content. TypeSafe receives selected source text to perform Jev analysis; its processing and retention are governed by TypeSafe's own terms and privacy documentation.

Operational logs

The analysis proxy's application logs are intentionally limited to operational information such as request status, latency, bounded input size, question count, usage information and an error category. It does not intentionally log PDF text, filenames or search query contents. Cloudflare may process standard infrastructure metadata needed to deliver the service and protect it from abuse.

Third parties and analytics

  • Cloudflare: hosts the static app and the Hono API proxy.
  • TypeSafe Jev: evaluates the selected source passages and reading objective sent by the proxy.
  • Google Fonts: the app requests its interface fonts from Google Fonts when the stylesheet loads.

JevReader does not use analytics, advertising, account providers, payment processors or a third-party analytics SaaS in the current pilot.

Authentication and payments

There is no user account, sign-in or payment functionality. A private pilot may optionally require a server-side pilot token, but that token is not an identity system and is not stored in your document cache.

Security model

The TypeSafe API key is kept as a server-side deployment secret and is never placed in browser-visible configuration. Requests are schema-validated and bounded, origins are checked, and the proxy applies timeout and concurrency limits. These measures reduce exposure and abuse; no online service can guarantee absolute security.

Retention and deletion

JevReader itself does not retain the PDF or maintain a server-side document copy. To remove local data, clear JevReader's site data in your browser; this removes its IndexedDB cache and preferences. Exported PDFs are ordinary files saved wherever you choose and must be deleted from your device separately.

Selected text sent to TypeSafe is processed by that provider to answer the analysis request. Questions about provider-side processing or deletion should be directed to the provider under its applicable terms.

Your rights

Because most document data remains on your device and Ziduri does not maintain a user account, we generally cannot access or export your local PDF cache. You can clear it yourself at any time. If you have a privacy question or believe the service has processed personal information about you, contact us and we will explain what can be addressed from our side.

Changes to this policy

JevReader is an early-stage pilot. If it adds accounts, persistent document storage, OCR, analytics or another material data flow, this policy will be updated first and the version and effective date above will change.
